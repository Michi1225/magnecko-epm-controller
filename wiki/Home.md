## What the firmware does

The STM32 application controls a magnetic foot through two timed pulse outputs. A polled SOES EtherCAT slave supplies the command interface. A drive-style finite state machine gates network magnet commands, while a physical button provides a separate demagnetization path. Four Hall sensors feed an empirical force model; four inductive sensors provide a slip indication that can suppress the reported force.

The application also publishes a BNO086 IMU, an 8 by 8 TMF8829 distance frame and SNR, an ADC temperature reading, and charger voltage when charger communication is enabled. The current source defines `USE_BATTERIES`, so the charger is not initialized in the default configuration.

## Reading the documentation

The compiled [object dictionary](../Libs/SOES_Wrapper/autogenerated/slave_objectlist.c), [controller](../Libs/Controller/FootController.cpp), and [HAL callbacks](../Core/Src/main.cpp) are the primary references. The word “autogenerated” does not imply that all files in that directory agree: `slave.xml` still describes an older actuator interface. See [EtherCAT integration](EtherCAT-Interface.md) before importing an ESI into a master.

Timing values are nominal values derived from the configured clocks and timers, not measurements. Examples assume a functioning board and a master configuration reconciled with the compiled dictionary. The repository contains no board schematic, connector drawing, external EtherCAT master application, or project-specific automated hardware tests.
